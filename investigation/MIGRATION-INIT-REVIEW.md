# Migration-init review: TanStack.com

Nift 4.9.0's generated guidance was read and followed before the baseline work. Its original hashes are in init-guidance.json. It already says that authored/rendered/hybrid sources are independent choices, framework islands and neighboring build systems are valid, complete production costs matter, external inputs must be frozen, and compatibility stages are preferable to unapproved core changes. These were useful rails. The initial scaffold was correctly treated as a placeholder.

The campaign exposed several concrete additions that would improve that guidance. These are proposals for later guidance/tooling work; Nift was not changed.

| Proposed addition | Evidence from this migration |
| --- | --- |
| A static/client/request-time/server/service ownership ledger, with an example retaining a complete framework runtime | The useful boundary publishes docs inputs/projections through Nift while TanStack Start retains shared-shell/page SSR, session state, Router/Query/React and every backend. “Islands” alone does not explain this partial-stack case. |
| A request-state gate before accepting whole-page snapshots | The root creates a fresh partner-placement seed. A byte/hydration-compatible snapshot still froze real functionality, so that prototype was rejected before scaling. Check auth, personalization, experiments and generated session state as well as appearance. |
| Native update workflow branches in benchmark planning | Upstream docs are GitHub/R2 runtime inputs. Valid paths use a lighter path manifest; missing-path redirect lookup needs a full metadata scan. A Vite rebuild or eager redirect scan for every body edit would be unfaithful. |
| Separate build/publication, runtime ingestion, deployment and live integration scopes | Local Worker/R2 contracts and unchanged backend source are strong evidence, but do not prove live PostgreSQL, OAuth, AI, mail, uploads, external indexing or tenant deployment. Infrastructure work must not silently enter build timings. |
| An external-input inventory covering runtime examples and browser imports | Pinning docs repos was not enough for the Charts iframe. Actual rendering needed additional pinned demo data and frozen public CDN module bytes; matching a handled “render failed” state was insufficient. |
| Runtime-consumed source representations in rendered/hybrid guidance | A maintained document AST preserves rich React docs components more faithfully than inert HTML. The agent model retains explicit original/download projections, necessary blog Markdown, partner-dependent hosting sources and useful React code. Do not mandate a framework-free or Markdown-free result. |
| Cross-stage dependency and publication-version recipes | A React source change fans out to five framework projections. The resolver records actual reads, and a verified immutable revision prevents stale runtime manifests after publication. An unchanged-command cache without these boundaries would be incorrect. |
| Explicit forced/fresh command verification and rejected-cohort recording | --full initially forced Vite but not Nift composition. The cohort was rejected and retained, then corrected to build --all before final measurements. Fresh output reproduced 24,648 files byte-identically. |
| Same-window memory scopes and mixed workflow labels | Individual process/phase RSS and 50ms sampled descendant RSS are different metrics. A local native-cache refresh is not a production bundle rebuild or a dev/HMR result. |
| Repeated lifecycle-sample isolation and readiness semantics | Restore source **and derived publication** between identical add/rename/delete mutations; native primes must assert original state before refresh assertions. Native raw/artifact refresh and pre-derived Nift publication are different readiness contracts. Flattened agent packets also require explicit cross-framework coordination. |
| Three-way recommendation labels | Use “Upstream TanStack Start”, “Nift tanstack (authored-source)” and “Nift tanstack-agent (rendered-source)” consistently. A bare project name can make a migration preference sound like an upstream preference. |

The guidance did not force a false static rewrite or core modification. The largest improvement would be a worked partial-stack example with request-time ownership, external runtime inputs, exact production commands, native update branches and three distinct evidence levels: UI, local transport and live backend integration.
