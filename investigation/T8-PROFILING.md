# T8 initial measurements and profiling

Three serialized samples per initial case, shared pinned toolchain and machine. Full-publication medians: upstream 30.85s (30.46–33.06), Nift authored 44.17s (42.62–45.72), Nift rendered 36.88s (34.75–37.51). Unchanged normal commands: 31.31s (29.70–32.72), 16.67s (16.47–16.86), 7.55s (7.54–7.74). These are preliminary, not final five-sample results. Peak process RSS remains dominated by retained Vite bundling, around 4.4–4.5 GiB across full pipelines; Nift has not eliminated that cost.

An initial command defect forced Vite but omitted Nift --all. Those Nift full rows are preserved with a rejection receipt and replaced, not pooled. Corrected full forces all tracked composition outputs. Upstream full and all unchanged rows remain valid.

Separate CPU profiles capture original resolver, projection derivation and each publisher. Metadata processing repeatedly imports the server module and constructs Markdown excerpts it does not use. Authored resolution also constructs unused excerpts for ordinary non-reference files, and writes all resolved files again. Derivation repeats across the entire corpus on unchanged commands. Agent preparation spends time parsing maintained projections and repeats the same metadata work. Parent profiles include synchronous child wait time; their sample totals are profile duration, not a claim of aggregate CPU consumption.

A native docs-refresh harness calls the pinned upstream cache, origin resolver, tree builder, redirect collector and artifact cache with real owned local R2 and captured public inputs. It invalidates Query content/artifacts and rebuilds the same 1,659-path manifest after changed-document/config reads. It does not perform Vite rebuilds. The helper is compiled against unchanged upstream modules to avoid tsx loader overhead in final measurements. Source-run smoke evidence remains diagnostic. Timing and memory will cover the same complete compiled-helper process window, including startup and local R2 transport. Live edge cache purge, network latency and authenticated backend integration remain outside this scope.

T9 will reduce measured redundant work, preserve explicit dependencies and immutable publication versions, retain forced-full behavior, and rerun semantic/raw/lifecycle/browser/service gates. No framework/core removal or search simplification is proposed.

Final scope correction before measurement: the eager redirect-manifest refresh above is diagnostic. The pinned caller uses the lighter path manifest for valid docs and full redirects for missing-path resolution. T10 measures those actual branches separately; see T10-PROTOCOL.md.
